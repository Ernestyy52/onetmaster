# Visual M2 · สถานะบัญชีและกลับเข้าเกม

**สถานะ:** UI ในเกมพร้อมตรวจสำหรับหน้าที่ไม่ต้องเข้าสู่ระบบ; สถานะหลังเข้าสู่ระบบยังรอตรวจด้วยบัญชีทดสอบของ Claude. งานนี้ใช้ React/CSS เดิม ไม่มี asset ใหม่, asset ID, frame, anchor หรือ collision. Model/Effort ที่แนะนำสำหรับงาน UI นี้คือ GPT-6 Sol / Medium.

## เส้นทางและสถานะที่ต้องเห็น

| ช่วง | สิ่งที่ผู้เล่นเห็น | เกณฑ์รับ |
|---|---|---|
| เปิดเกม | ข้อความ `กำลังโหลด…` ก่อนตัดสินเส้นทาง | ไม่แสดงข้อมูลบัญชีระหว่างรอ |
| ยังไม่เข้าสู่ระบบ | `เข้าสู่ระบบ`, อีเมล, รหัสผ่าน, ปุ่มไปสร้างบัญชี | ปุ่มส่งกดได้เมื่อรูปแบบอีเมลและรหัสผ่าน ≥8 ตัว; ช่องและปุ่มสูง ≥44 CSS px |
| สร้างบัญชี | ฟอร์มชุดเดียวกัน เปลี่ยนหัวข้อ/ปุ่ม/ทางกลับ | ข้อความแนะนำให้ครูหรือผู้ปกครองช่วยตั้งค่า; หลังสร้างสำเร็จแนะนำยืนยันอีเมล |
| กำลังส่ง | ปุ่มหลักแสดง `กำลังดำเนินการ…` และปิดการกดซ้ำ | ห้ามสลับโหมดระหว่างคำขอ; ยังคงค่าที่กรอกไว้ |
| ข้อผิดพลาดของฟอร์ม | ข้อความในกรอบฟอร์ม มีสีเตือนและ `role=alert` | แสดงข้อความเพียงแห่งเดียว ไม่บังปุ่มและช่องกรอก |
| โหลดข้อมูลบัญชีผิดพลาด | ข้อความเชื่อมต่อไม่สำเร็จในฟอร์ม พร้อม `ลองเชื่อมต่ออีกครั้ง` | กดซ้ำได้โดยไม่ต้องกรอกข้อมูลใหม่; ผลใหม่แทนข้อความเดิม |
| เข้าสู่ระบบแล้ว | หน้า Title → เลือกตัวละครหรือเล่นต่อ | แสดงเฉพาะชื่อเล่นตัวละครและความคืบหน้าเกม ไม่แสดงอีเมลในหน้าเลือกตัว |
| หลุดระหว่างเล่น / กลับเข้าเกม | กลับไปหน้าเข้าสู่ระบบเมื่อ session หมด; เมื่อ session ยังอยู่ ให้โหลดเซฟแล้วไป Title | อย่าแสดงสถานะสำเร็จก่อนเซิร์ฟเวอร์ตอบ; ทดสอบกับบัญชีจริงสองอุปกรณ์ก่อนปิด M2 |

## กฎภาพและการจัดวาง

- ใช้พื้นหลังม่วงเข้ม, panel ขอบสว่าง, สีทองกับหัวเรื่อง/โฟกัส และปุ่มหลักสีส้มตาม UI เดิม. ข้อความผิดพลาดใช้สีเตือนพร้อมข้อความ ไม่พึ่งสีอย่างเดียว.
- จอ 360×800: ฟอร์มกว้างตามพื้นที่ว่าง ขอบอย่างน้อย 16 px, ไม่มีล้นแนวนอน, ส่วนท้ายและปุ่มสลับโหมดยังเลื่อนถึงได้เมื่อมีข้อความผิดพลาด. จอกว้าง: panel กว้างไม่เกิน 520 px.
- `.screen` และ `.modal-backdrop` ต้องบวก safe-area inset ของทุกด้าน; modal จำกัดความสูงตาม top/bottom inset. CSS นี้อยู่ใน M1 visual commit `7ae627c` และถูกนำมาปรับใน M2 แล้ว.
- ใช้ชื่อเล่นในเกมเท่านั้นบน Title/เลือกตัวละคร. ข้อความบัญชีเป็นเพียงบริบทการบันทึกและคำแนะนำครู/ผู้ปกครอง; หลีกเลี่ยงข้อมูลเด็กเพิ่มเติม.

## ตรวจภาพจริงและข้อจำกัด

- ตรวจหน้าเข้าสู่ระบบบน browser ที่ 1366×768 และ 360×800 และหน้าสร้างบัญชีที่ 360×800: ตัวหนังสือ/ช่อง/ปุ่มอยู่ใน panel, ปุ่มสลับโหมดแตะได้, ไม่เห็นการล้นแนวนอน. ตรวจรูปและ accessibility tree ของทั้งสองสถานะ.
- ตรวจจากโค้ดว่า disabled ของปุ่มส่ง, busy label, error alert และปุ่มลองเชื่อมต่ออยู่ใน `AuthScreen`; global error banner ไม่ซ้ำบนหน้า auth.
- ยังไม่ได้ส่งฟอร์ม, ใช้บัญชีจริง, ทำให้เครือข่ายขาด, ตรวจ keyboard บนโทรศัพท์จริง หรือยืนยันเส้นทางเลือกตัวละคร/กลับเข้าเกมของ online build. Claude ต้องตรวจกรณีเหล่านี้ระหว่าง online integration ของ M2.
